A DMA transfer controller pipeline at `/app/pipeline.py` simulates a scatter-gather DMA engine managing multi-channel memory transfers with priority arbitration, burst sizing, and completion interrupts. It uses modules `/app/channel_arbiter.py`, `/app/burst_calculator.py`, `/app/scatter_gather.py`, `/app/address_translator.py`, `/app/completion_handler.py`, and `/app/dma_reporter.py`.

Run it with `python3 /app/pipeline.py`. It reads `/app/dma_config.json` and writes `/app/output.json`.

The pipeline produces correct output on the current configuration but has bugs that cause incorrect transfer scheduling, burst sizing, and preemption behavior on other configurations. Find and fix the bugs so the controller handles all valid DMA configurations correctly.

Arbitration contract: in each cycle the controller schedules the enabled channel that still has bytes outstanding and carries the lowest configured `priority` value. The urgency-adjusted effective priority governs preemption eligibility only — it never influences which channel is scheduled. Preemption is recorded rather than enacted: a preempted channel keeps the bus for that cycle and still advances by one burst, the preempting channel is not scheduled in its place, the cycle still counts as a transfer operation, and `preemption_count` is credited to the channel that was preempted. A preempted cycle may also be the cycle on which that channel completes.

Do not rewrite from scratch — preserve the existing module structure. In particular, preserve the completion handler's write-1-to-clear interrupt convention — bits are asserted by hardware and accumulate for the whole run, never acknowledged or cleared by the pipeline — and the address translator's negative bus-window translation, where the bus address is the physical address minus `bus_offset`. The fixed pipeline will be tested on different configurations than the one at `/app/dma_config.json`.

Output: `/app/output.json` — a JSON object with fields: `summary` (total_bytes_transferred, total_transfer_operations, total_preemptions, total_cycles_used, completed_transfers, average_burst_size), `transfers` (list of per-cycle transfer records with cycle, channel_id, source_bus_addr, dest_bus_addr, burst_size, total_transfers, bytes_transferred, chain_length, preempted, complete), `channel_statistics` (per-channel channel_id, priority, total_bytes, transfer_count, preemption_count, efficiency), `interrupt_log` (per-event channel_id, cycle, status_hex, completion_pending, error_pending), and `performance` (bus_utilization, average_latency_cycles, throughput_bytes_per_cycle). Every field above is compared exactly.
