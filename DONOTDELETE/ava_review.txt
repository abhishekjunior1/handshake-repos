## WHAT IS QC_GATE? (replaced old AVA as the main gate)
- Runs AFTER pass2, BEFORE trials
- qc_eval (LLM static analysis, ~8-13 min) + qc_exec (execution probes, ~3-8 min)
- Both must PASS → if either fails, gate blocks, trials skipped
- 30 checks across 5 families: A (oracle), B (spec), C (verifier), D (fixtures), E (anti-cheat)

## THE NEW PROVEN PATTERN (passes ALL checks)

### Architecture:
1. Eval configs in /app/ (environment/data/) — agent-visible during agent run
2. instruction.md tells agent to run pipeline on eval configs and save outputs
3. Agent fixes bugs + runs pipeline during ITS OWN run
4. test.sh ONLY runs pytest — NEVER runs agent code
5. Expected outputs as plain JSON in tests/

### test.sh (copy exactly):
```bash
#!/bin/bash
mkdir -p /logs/verifier

echo "0" > /logs/verifier/reward.txt

# Agent was instructed to run pipeline on eval configs during its turn.
# Verifier only reads pre-existing outputs — never re-runs agent code.
pytest --ctrf /logs/verifier/ctrf.json /tests/test_outputs.py -rA

if [ $? -eq 0 ]; then
  echo "1" > /logs/verifier/reward.txt
else
  echo "0" > /logs/verifier/reward.txt
fi
```

## HOW TO PASS EACH COMMON CHECK

### A6 (Oracle Edge-Case) — usually FALSE POSITIVE
- QC confuses output-shaped standalone files with input files
- Fix: ONLY plain JSON in tests/ — no conftest.py, expected_data.py with dicts
- If still blocking: rename files or push new commit to bust stale QC cache

### B6 (Unstated Data Anomaly) — CATCH-22
- Document → rubric fails "essential_difficulty"; Don't → QC flags B6
- Solution: Use 2 eval configs with DIFFERENT service/key structures
  so hardcoding one config's answer fails the other

### E3 (Reward Exploit):
- Fix: NEVER run pipeline.py in test.sh

### E4 (Root/Elevated Access):
- Fix: Agent runs pipeline in agent phase; /tests/ not mounted then

### E5 (Symlink):
- Fix: assert not os.path.islink(path) + realpath check in _load_output()

### AVA sound_verifier (hardcoding concern):
- Fix: Add input-derivation test that reads /app/eval_config.json and
  cross-checks output fields derived from that specific input's values
- Example: read VERSION env var from eval config, verify output contains
  the expanded value (proves pipeline was run, not output hardcoded)

### AVA FAILURE: String sort of integer-derived window IDs (run 2 → run 3)
**What happened:**
- Pipeline used `sorted(windowed_events.keys())` — string sort on window IDs like "16", "17", "18"
- AVA flagged: for window IDs across decades (e.g. "9" and "16"), string sort ≠ integer sort → coverage gap
- Our eval datasets only had 2-digit IDs (same width), so string == integer in practice
- But AVA reasons about the GENERAL CASE, not just our specific data

**Fix:**
```python
window_ids = sorted(windowed_events.keys(), key=int)
```

**And add to test_outputs.py:**
```python
def test_window_ids_order(self):
    """Window IDs must appear in ascending integer order."""
    out = _load_output("/app/output_eval_1.json")
    exp = _load_expected("expected_eval_1.json")
    out_ids = [w["window_id"] for w in out["windows"]]
    exp_ids = [w["window_id"] for w in exp["windows"]]
    assert out_ids == exp_ids, f"Window ID order: got {out_ids}, expected {exp_ids}"
```

### deep_review FAILURE: no_contradictions (run 3 → run 4)
**What happened:**
- pipeline.py had comment: "Raw event volume reflects true sensor load for rate estimation, independent of semantic deduplication which applies to alert triggering only."
- Code right after: `compute_window_stats(events=deduped_events, count=effective_count, ...)`
- The comment said "raw event volume" but code used deduped events
- One pass2 agent correctly fixed both bugs, then read this comment and changed rate_calculator.py to use raw events — causing failure
- deep_review flagged: `no_contradictions FAIL`, `decisive_answer_discoverable FAIL`

**Fix:** Delete the misleading comment entirely. 3 lines removed.

**RULE:** Any comment near a bug that says "raw", "volume", or describes what the parameter SHOULD be must be removed if it contradicts the correct behavior. If the comment was placed there to "justify" the buggy value, it creates a spec contradiction.

### pass2 FAILURE: Undisclosed baseline convention (run 4 → run 5)
**What happened:**
- Bug 2 (EMA smoothing) was correctly removed by one agent
- Agent then additionally changed `baseline=global_baseline` → leave-one-out baseline (excluding current window)
- Leave-one-out is a LEGITIMATE statistical practice for anomaly detection
- instruction.md only protected "IQR capping" and "cumulative mean_value" as intentional
- The global baseline convention was never disclosed
- pass2 classified it as `approach_validity: FAIL` (spec gap, not valid agent failure)

**Fix:** Add to instruction.md's "intentional behaviors" sentence:
```
Anomaly scoring uses a self-inclusive global baseline — all windows' rate 
statistics are used as the baseline when scoring each window.
```

**RULE:** For ANY computation where multiple valid implementations exist, instruction.md MUST pin the specific convention used. Common alternatives agents will try:
- Leave-one-out vs self-inclusive baseline
- Sample variance (ddof=1) vs population variance (ddof=0)
- Mean vs median for baseline
- Global normalization vs per-group normalization
- Chronological ordering vs alphabetical ordering
