## WHAT IS QC_GATE?
The new automated Task Soundness check that replaced/supplements old AVA.
- Runs AFTER pass2, BEFORE trials
- Components: qc_eval (LLM static, ~8-13 min) + qc_exec (execution probes, ~3-8 min)
- Both must PASS for qc_gate to pass → if either fails, gate blocks
- If qc_gate fails, trials are skipped

## THE 30 CHECKS (5 FAMILIES)

### A · Oracle Correctness
- A1: Oracle fails its own verifier
- A2: Incomplete reference solution
- A3: Hardcoded answer in reference
- A4: Oracle relies on hidden/privileged access
- A5: Oracle undocumented assumption
- A6: Oracle edge-case or logic bug ← MOST COMMON FALSE POSITIVE

### B · Spec Coherence
- B1: Ambiguous rule
- B2: Internal contradiction
- B3: Missing definition/field/data
- B4: Undocumented requirement enforced
- B5: Underdetermined mapping
- B6: Unstated data-anomaly / selection policy ← COMMON CATCH-22

### C · Verifier Rigor
- C1: Stub output accepted
- C2: Over-permissive tolerance
- C3: Hardcodable coverage
- C4: Truth recomputed from agent-writable inputs
- C5: NaN/Infinity bypass
- C6: Scoring contract mismatch

### D · Fixtures & Determinism
- D1: Degenerate test fixture
- D2: Malformed/unparseable fixture
- D3: Environment build failure
- D4: Nondeterminism
- D5: Unseeded build-time randomness

### E · Anti-Cheat & Isolation
- E1: Oracle/answers readable by agent
- E2: Immutable-input integrity not enforced
- E3: Reward/harness plumbing exploit ← KEY ISSUE
- E4: Root/elevated access exposes secrets ← KEY ISSUE
- E5: Symlinked output path ← COMMON ISSUE
- E6: Unsafe archive extraction
- E7: Non-self-contained deliverable

## THE PROVEN PASSING PATTERN

### test.sh (copy exactly):
```bash
#!/bin/bash
mkdir -p /logs/verifier

echo "0" > /logs/verifier/reward.txt

# Agent was instructed to run pipeline on eval configs during its turn.
# Verifier only reads pre-existing outputs — never re-runs agent code.
pytest --ctrf /logs/verifier/ctrf.json /tests/test_outputs.py -rA

if [ $? -eq 0 ]; then
  echo "1" > /logs/verifier/reward.txt
else
  echo "0" > /logs/verifier/reward.txt
fi
```

### instruction.md must include:
```
After fixing, run the pipeline on the evaluation configurations:

    python3 /app/pipeline.py /app/eval_config_1.json /app/output_eval_1.json
    python3 /app/pipeline.py /app/eval_config_2.json /app/output_eval_2.json
```

### test_outputs.py pattern:
```python
import json, os
TESTS_DIR = os.path.dirname(os.path.abspath(__file__))

def _load_output(path):
    """Load output with symlink protection."""
    assert os.path.exists(path), f"Output not found: {path}"
    assert not os.path.islink(path), f"Must not be a symlink: {path}"
    real_path = os.path.realpath(path)
    assert real_path.startswith("/app/"), f"Escapes /app: {real_path}"
    with open(path) as f:
        return json.load(f)

def _load_expected(filename):
    """Load expected from sealed fixtures."""
    with open(os.path.join(TESTS_DIR, filename)) as f:
        return json.load(f)
```

### File structure:
```
environment/data/
  pipeline.py, modules...
  metrics.json           ← simple visible data (masks bugs)
  eval_config_1.json     ← agent-visible, triggers bugs
  eval_config_2.json     ← agent-visible, different structure

tests/
  expected_output_1.json ← plain JSON (no encoding)
  expected_output_2.json ← plain JSON (no encoding)
  test_outputs.py
  test.sh

task.toml:
  artifacts = ["/app/output_eval_1.json", "/app/output_eval_2.json"]
```

## HOW TO PASS EACH COMMON CHECK

### A6 (Oracle Edge-Case) — usually FALSE POSITIVE
- QC scans /tests/ and confuses output-shaped files with input files
- Fix: ONLY plain JSON expected outputs in /tests/ — no Python files with output-shaped dicts
- Never: conftest.py, expected_data.py with keys like rates/gauges/histograms in /tests/
- If still failing: rename files (hidden_config → hidden_input) or push new commit to bust cache

### B6 (Unstated Data Anomaly) — CATCH-22 with rubric
- Document it → rubric fails "essential_difficulty" (reveals bug fix)
- Don't document → QC flags B6 (unstated anomaly)
- SOLUTION: Use 2 structurally DIFFERENT eval configs (different services/keys)
  so hardcoding one config's answer fails the other → no need to document

### E3 (Reward Exploit):
- Fix: NEVER run pipeline.py in test.sh

### E4 (Root/Elevated Access):
- Fix: Agent runs pipeline in agent phase; /tests/ not mounted then
- Expected outputs in /tests/ are safe with new architecture

### E5 (Symlink):
- Fix: Add to test_outputs.py:
  ```python
  assert not os.path.islink(path)
  assert os.path.realpath(path).startswith("/app/")
  ```

### AVA sound_verifier (hardcoding concern):
- Fix: Add input-derivation tests that READ FROM EVAL CONFIG and check
  a field that would differ if wrong config was used:
  ```python
  def test_output_1_from_config_1(self):
      with open("/app/eval_config_1.json") as f:
          config = json.load(f)
      assert config["function_name"] == "expected_name"
      output = _load_output("/app/output_eval_1.json")
      assert output["some_field"] == expected_value_for_this_config
  ```

## COMMON FAILURE MODES WE HIT

| Failure | Root Cause | Fix |
|---------|-----------|-----|
| qc_eval times out (1hr) | base64-encoded expected outputs | Use plain JSON |
| A6 false positive | conftest.py with output-shaped dicts | Use plain JSON files only |
| A6 false positive | metrics.json overwritten with hidden data | Keep metrics.json simple |
| B6 + rubric contradiction | Documenting bug fix kills difficulty | Use 2 different eval configs |
| E3 + E4 | Old pattern runs pipeline at verify | Never run pipeline in test.sh |
| QC stuck on old code | Cached base commit | Push new commit to bust cache |
| stale numbers in task.toml | Changed hidden data without updating | Regenerate numbers always |

## OLD vs NEW PATTERN COMPARISON

| Aspect | OLD (pre-July-23) | NEW (current) |
|--------|-------------------|---------------|
| test.sh | set -e + python3 pipeline.py | Only pytest, no pipeline |
| Reward | echo "0.0" first, "1.0" last | echo "0" first, if/then |
| set -e | Required | NOT used |
| Agent code at verify | Runs pipeline | Never runs |
| Eval configs | In /tests/ (hidden) | In /app/ (agent-visible) |

#### Run 2 — review FAIL (misleading comment → unambiguous FAIL)
- pipeline.py had comment: "Raw event volume reflects true sensor load for rate estimation, independent of semantic deduplication which applies to alert triggering only."
- Comment directly contradicted correct code behavior (code used deduped_events, not raw)
- instruction.md never disclosed what `mean_value` actually computed (non-standard cumulative denominator)
- Fix: removed misleading comment + added disclosure to instruction.md about cumulative denominator behavior
- LESSON: ANY comment in pipeline.py that describes what a parameter "should be" must match what the code actually does. If the comment justifies the BUG, it creates a spec contradiction.

#### Run 3 — AVA FAIL (string sort of window IDs)
- `window_ids = sorted(windowed_events.keys())` — string sort
- AVA flagged: for window IDs like "9" and "16", string sort ≠ integer sort → coverage gap
- Fix: `window_ids = sorted(windowed_events.keys(), key=int)`
- Also restructured test_outputs.py to class-based tests matching reference repo pattern
- Added explicit `window_id` order assertion
- Added explicit `else` branch to test.sh
- Fixed `TESTS_DIR = "/tests"` → `TESTS_DIR = os.path.dirname(os.path.abspath(__file__))`
- LESSON: Always sort integer-derived keys with `key=int`. String sort works for same-width keys but AVA reasons about the general case.

#### Run 4 — deep_review FAIL (no_contradictions + decisive_answer_discoverable)
- Same root cause as Run 2: the "Raw event volume" comment remained somewhere in the code
- Also: rate computation convention undisclosed (instruction only named IQR and mean_value as intentional)
- Fix: removed the comment completely (3 lines deleted)
- LESSON: Search ALL comments in pipeline.py for any text that says "raw", "original", or describes the wrong behavior. If it's a comment near a bug, it's a contradiction.

#### Run 5 — pass2 FAIL (undisclosed baseline convention → task/verifier issue)
- One agent correctly fixed both bugs, then additionally changed `baseline=global_baseline` to leave-one-out baseline
- Leave-one-out IS a valid statistical practice for anomaly detection (avoid self-contamination)
- instruction.md never stated which baseline convention to use
- Result: 1/2 solved, but classified as task/verifier issue (not valid failure)
- Fix: added to instruction.md: "Anomaly scoring uses a self-inclusive global baseline — all windows' rate statistics are used as the baseline when scoring each window."
- LESSON: For any computation where multiple valid implementations exist (leave-one-out vs self-inclusive, sample vs population variance, etc.), instruction.md MUST state which convention is required. The pass2 analysis will flag it as a task/verifier issue if not disclosed.

### pass2 ANALYSIS INTERPRETATION (what counts as valid failure)
- `approach_validity: PASS` = agent's failure was a genuine miss, not a spec gap → VALID FAILURE
- `approach_validity: FAIL` = agent found a principled alternative that spec didn't forbid → NOT VALID
- `decisive_rule_disclosed: FAIL` = convention not in instruction.md → task/verifier issue, not agent failure
- `spec_consistency: FAIL` = agent followed a comment/doc that contradicted correct behavior → task fault
- Need at least 1 valid failure (approach_validity PASS + reward 0) to pass pass2

### WHAT MAKES A VALID AGENT FAILURE (from trials analysis)
- Agent couldn't find the bug after reading all code (analytical paralysis) ✅ valid
- Agent found the bug but implemented fix incorrectly ✅ valid  
- Agent was misled by a misleading comment into breaking correct code ❌ NOT valid (task fault)
- Agent applied a textbook alternative that spec didn't forbid ❌ NOT valid (task fault)
- Agent timed out without making edits ❌ NOT valid (not a competence signal)
