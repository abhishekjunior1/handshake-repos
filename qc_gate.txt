## WHAT IS QC_GATE?
The new automated Task Soundness check that replaced/supplements old AVA.
- Runs AFTER pass2, BEFORE trials
- Components: qc_eval (LLM static, ~8-13 min) + qc_exec (execution probes, ~3-8 min)
- Both must PASS for qc_gate to pass → if either fails, gate blocks
- If qc_gate fails, trials are skipped

## THE 30 CHECKS (5 FAMILIES)

### A · Oracle Correctness
- A1: Oracle fails its own verifier
- A2: Incomplete reference solution
- A3: Hardcoded answer in reference
- A4: Oracle relies on hidden/privileged access
- A5: Oracle undocumented assumption
- A6: Oracle edge-case or logic bug ← MOST COMMON FALSE POSITIVE

### B · Spec Coherence
- B1: Ambiguous rule
- B2: Internal contradiction
- B3: Missing definition/field/data
- B4: Undocumented requirement enforced
- B5: Underdetermined mapping
- B6: Unstated data-anomaly / selection policy ← COMMON CATCH-22

### C · Verifier Rigor
- C1: Stub output accepted
- C2: Over-permissive tolerance
- C3: Hardcodable coverage
- C4: Truth recomputed from agent-writable inputs
- C5: NaN/Infinity bypass
- C6: Scoring contract mismatch

### D · Fixtures & Determinism
- D1: Degenerate test fixture
- D2: Malformed/unparseable fixture
- D3: Environment build failure
- D4: Nondeterminism
- D5: Unseeded build-time randomness

### E · Anti-Cheat & Isolation
- E1: Oracle/answers readable by agent
- E2: Immutable-input integrity not enforced
- E3: Reward/harness plumbing exploit ← KEY ISSUE
- E4: Root/elevated access exposes secrets ← KEY ISSUE
- E5: Symlinked output path ← COMMON ISSUE
- E6: Unsafe archive extraction
- E7: Non-self-contained deliverable

### pass2 ANALYSIS INTERPRETATION (what counts as valid failure)
- `approach_validity: PASS` = agent's failure was a genuine miss, not a spec gap → VALID FAILURE
- `approach_validity: FAIL` = agent found a principled alternative that spec didn't forbid → NOT VALID
- `decisive_rule_disclosed: FAIL` = convention not in instruction.md → task/verifier issue, not agent failure
- `spec_consistency: FAIL` = agent followed a comment/doc that contradicted correct behavior → task fault
- Need at least 1 valid failure (approach_validity PASS + reward 0) to pass pass2

### WHAT MAKES A VALID AGENT FAILURE (from trials analysis)
- Agent couldn't find the bug after reading all code (analytical paralysis) ✅ valid
- Agent found the bug but implemented fix incorrectly ✅ valid  
- Agent was misled by a misleading comment into breaking correct code ❌ NOT valid (task fault)
- Agent applied a textbook alternative that spec didn't forbid ❌ NOT valid (task fault)
- Agent timed out without making edits ❌ NOT valid (not a competence signal)

### C2 (Over-permissive tolerance) — approx_equal exact-zero fix

**What failed:**
`approx_equal(a, 0.0)` used the `abs(b) < 1e-10` branch which accepts any `a < 1e-6`.
For p_value=0.0 fields this is way too loose.

**Fix:**
```python
def approx_equal(a, b, rel_tol=1e-3):
    if isinstance(a, (int, float)) and isinstance(b, (int, float)):
        if b == 0.0:           # CRITICAL: exact zero must match exactly
            return a == 0.0
        if abs(b) < 1e-10:
            return abs(a) < 1e-6
        return abs(a - b) / abs(b) < rel_tol
    return a == b
```

### qc_gate BLOCK: B5 — Underdetermined / Hidden-Knowledge Mapping (Push 6)

**CI message:**
```
1. Underdetermined / Hidden-Knowledge Mapping — dataset.json

What this means: The expected output can't be worked out from the information 
given — it needs knowledge the task-taker doesn't have.

What we found: Disclosed example dataset.json has only single-batch streams, 
so evidence-weight rule sum(log_marginals) == rival rule sum/len (matching 
pristine docstring 'normalized by the batch count'). Rival solver (3 math 
fixes, keep sum/len) produces output IDENTICAL to correct on dataset.json 
(lews -1.666547...).

Fix: Give enough spec/examples to determine the mapping from visible inputs, 
or document the rule.
```

**Root cause in detail:**

The 4th bug was in `predictive_reporter.py:compute_stream_evidence_weight`:
```python
# BUG — wrong:
total_log_evidence = sum(log_marginals) / len(log_marginals)

# CORRECT:
total_log_evidence = sum(log_marginals)
```

The comment justified it as "scale-invariant per-batch score". BUT:

`dataset.json` had exactly 1 batch per stream → `sum([x]) / 1 == sum([x])`

So a solver who:
- Fixed bugs 1, 2, 3 (module formula bugs) ✓
- KEPT the `sum/len` bug ✗

...would produce output **mathematically identical** to the oracle on `dataset.json`.
QC flagged this as B5: the rule cannot be determined from visible inputs.

**The masking strategy (single-batch visible data) BACKFIRED for qc_gate.**
While it successfully masked the bug from agents, it also made the rule undiscoverable
by qc_gate's analysis.

**Fix:** Added ONE sentence to instruction.md:

```
BEFORE:
"...Find and fix the bugs so the pipeline handles all valid configurations correctly.
Do not rewrite from scratch — preserve the existing module structure."

AFTER:
"...Find and fix the bugs so the pipeline handles all valid configurations correctly.
Do not rewrite from scratch — preserve the existing module structure. The per-stream
log evidence weight is the cumulative sum of the per-batch log marginal likelihoods
(not normalized by batch count)."
```

**Why this works:**
- Discloses the RULE (cumulative sum, not mean) — makes it discoverable
- Does NOT reveal WHERE the bug is (agent still must find `sum/len` in 1550 lines)
- Does NOT reduce difficulty for the other 3 bugs (different files/formulas)
- qc_gate B5 satisfied: solver can now determine the correct behavior

**LESSON: Masking + qc_gate tension**

When you mask a bug using degenerate visible data (e.g., n=1 so sum/n = sum), 
qc_gate may flag it as B5 (underdetermined). The fix is always to DISCLOSE the 
RULE in instruction.md without revealing the BUG LOCATION.

Examples:
- Bug: `sum(log_marginals) / len(log_marginals)` masked by n=1 batches
  → Disclose: "log evidence weight is cumulative sum of per-batch marginals"
  
- Bug: wrong df in t-test masked by single comparison
  → Disclose: "degrees of freedom use q-1 where q is number of groups"

- Bug: wrong variance formula masked by uniform data  
  → Disclose: "variance uses Bessel's correction (ddof=1)"

The pattern: describe WHAT the correct behavior is (the rule), not WHERE or HOW
to find the bug.
