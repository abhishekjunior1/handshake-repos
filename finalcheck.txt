## PART 1 — CI PIPELINE ORDER

review → similarity → ratelimit → validation → pass2 → tier1
→ [parallel] ava_review + adversarial_review + deep_review
→ qc_eval + qc_exec → qc_gate → trials → gate

Each stage gates the next. If any fails, later stages are skipped.
Total wall time: ~2-4 hours for a clean run.
Rate limit: 6 CI runs per day per task.

### 3c. _load_output (copy into test_outputs.py)
  def _load_output(path):
      """Load agent-produced output with symlink and hardlink protection."""
      assert os.path.exists(path), f"Output not found: {path}"
      assert not os.path.islink(path), f"Must not be a symlink: {path}"
      real_path = os.path.realpath(path)
      assert real_path.startswith("/app/"), f"Path escapes /app: {real_path}"
      out_stat = os.stat(path)
      assert out_stat.st_nlink == 1, f"Output has multiple hard links"
      with open(path, "r") as f:
          return json.load(f)

### 3d. approx_equal (copy into test_outputs.py)
  def approx_equal(a, b, rel_tol=1e-3):
      """Approximate equality — exact zero must match exactly."""
      if isinstance(a, (int, float)) and isinstance(b, (int, float)):
          if b == 0.0:
              return a == 0.0          # CRITICAL: p_value=0.0 must match exactly
          if abs(b) < 1e-10:
              return abs(a) < 1e-6
          return abs(a - b) / abs(b) < rel_tol
      return a == b

### 3e. input-derivation test (adapt for your task)
  def test_eval1_output_derived_from_input():
      """Prove output was computed by running the fixed pipeline on THIS specific input.
      Reads raw config and checks values that require running the fixed pipeline.
      """
      with open("/app/eval_config_1.json") as f:
          config = json.load(f)
      out = _load_output("/app/output_eval_1.json")

      # Structural tie to THIS config (not eval2 — must differ between evals)
      expected_ids = {s["session_id"] for s in config["sessions"]}
      assert {s["summary"]["session_id"] for s in out["sessions"]} == expected_ids
      assert out["session_count"] == len(config["sessions"])

      # Bug discriminator — value requires running FIXED pipeline, not readable from config
      # Threshold must DIFFER from eval2's threshold to block cross-config copying
      assert out["total_verification_failures"] == 0, \
          f"failures={out['total_verification_failures']} — bugs not fixed"

  def test_eval2_output_derived_from_input():
      """Same as eval1 but with DIFFERENT structural checks — prevents hardcoding."""
      with open("/app/eval_config_2.json") as f:
          config = json.load(f)
      out = _load_output("/app/output_eval_2.json")
      # eval2 has different session IDs and record counts than eval1
      expected_ids = {s["session_id"] for s in config["sessions"]}
      assert {s["summary"]["session_id"] for s in out["sessions"]} == expected_ids
      total_recs = sum(len(s["records"]) for s in config["sessions"])
      assert out["total_application_records"] == total_recs
      assert out["total_verification_failures"] == 0

### CHECK 11: output schema is enumerated PER SECTION (added Jul 30 — cost 1 push)
  Never grep the whole instruction for a field name. A field named anywhere else
  (e.g. "priority" appearing in a prose rule about the CONFIG) makes a naive
  substring check report "documented" when that section never lists it.
  Compare each section's parenthetical against THAT section's real keys:

  python3 - <<'EOF'
  import json, re
  exp  = json.load(open('task/tests/expected_output_1.json'))
  inst = open('task/instruction.md').read()
  PROSE = {'per','channel','event','list','of','with','and','totals','record','records'}
  ok = True
  for name, v in exp.items():
      m = re.search(r'`%s` \(([^)]*)\)' % name, inst)
      if not m:
          print(f'FAIL {name}: no enumeration in instruction.md'); ok = False; continue
      listed = {t.strip().split()[-1] for t in m.group(1).split(',') if t.strip()}
      actual = set(v[0]) if isinstance(v, list) else set(v)
      missing, spurious = sorted(actual - listed), sorted(listed - actual - PROSE)
      if missing or spurious: ok = False
      print(f'{"OK  " if not (missing or spurious) else "FAIL"} {name}: '
            f'missing={missing or "-"} spurious={spurious or "-"}')
  print('exact 1:1:', ok)
  EOF
  # missing  = graded but undocumented -> ava_review/no_false_rejection BLOCK
  # spurious = documented but not graded -> agent builds a field nothing wants

  A rule a config triggers but you never state -> qc_gate B1/B4 BLOCK.

### CHECK 14: rival-reading test (catches qc_gate B1 before CI does)
  For every rule with two defensible readings, IMPLEMENT the rival reading on top of
  the full fix and run it against every graded fixture.
    - rival output == oracle output on all fixtures -> unpinned but harmless
    - rival differs on ANY fixture and instruction.md does not forbid it -> B1 BLOCK
  Fix by pinning the deciding choice in instruction.md — pin ONLY the choice that
  changes the graded answer, never the method that reveals a bug.

### CHECK 15: every bug must be load-bearing (added Aug 1 — cost 1 redesign cycle)
  A bug that another layer silently compensates for is a free pass: the agent fixes
  n-1 bugs and still scores 1. Run ALL proper subsets of your fixes, not just "none"
  and "all". With 3 bugs that is 6 runs; every one must score 0.

  for c in "1" "2" "3" "1,2" "1,3" "2,3"; do run_with_only_those_fixes "$c"; done
  # every line must print reward=0

  How it bit us (dynamo-qffewau): the variable-expansion bug wrote
  `tag=$ARTIFACT_TAG` into a double-quoted shell command, so the SHELL re-expanded it
  from the environment and produced the correct file anyway. Fixing bugs 2+3 alone gave
  byte-perfect output. Fix was to single-quote the write so the shell cannot paper over
  Python's failure. Watch for compensators generally: shell expansion, defaults,
  clamps, retries, `or`-fallbacks.

### CHECK 16: pin any agent-writable input the VERIFIER derives from (E2)
  If tests compute expected values from a file under /app, the submission can edit that
  file to bend the expectations. Hash-pin it and check inside the loader so every
  derivation path is covered by construction:

    def load_taskfile(path):
        raw = open(path,'rb').read()
        assert hashlib.sha256(raw).hexdigest() == PINNED[path], f"{path} was modified"
        return json.loads(raw)

  Then add a named test per input so tampering fails loudly instead of silently
  shifting what "expected" means. Verify with a tamper probe: edit the input, solve
  correctly against the EDITED file, and confirm reward=0.

### CHECK 17: tests/ must not contain a copyable answer (qc_gate C3)
  If tests/expected_output.json is byte-identical to what the agent must produce, then
  anywhere it is readable, `cp` beats the task — and NO content assertion can detect it,
  because the copy IS the correct answer. Input-derivation tests do not help.
  Ship logic, not an answer:
    - derive granular expectations from the agent-visible inputs (pinned per CHECK 16)
    - pin whole-output exactness with a SHA-256 over a canonical projection that drops
      wall-clock fields — a digest cannot be copied into /app as a passing output
  Probe: `cp /tests/<any fixture> /app/<output>` must score 0, and `ls tests/` should
  show no file shaped like the deliverable.

### CHECK 18: keep the verifier in ONE file
  73 of 74 accepted tasks ship tests/test_outputs.py with no helper module. A separate
  module in tests/ is the outlier, and AVA reads one as "the verifier imports its oracle
  module". Inline the helpers. (qc_gate.txt says the same for a different reason:
  "ONLY plain JSON expected outputs in /tests/ — no Python files".)

## PART 7 — BUG DESIGN (what works vs what fails)

### WHAT FAILS (7/7 self-play — never use):
  - Argument order swaps: compute_fn(a, b) instead of compute_fn(b, a) — agents read sig, instant fix
  - Formula errors: wrong constant, wrong exponent — models know all formulas
  - Docstring contradicts code — agents spot this immediately
  - Wrong function called when right function has a similar name nearby
  - Any bug a model can verify by "checking textbook"

### WHAT WORKS (0/5 CI):
  - CROSS-MODULE DATA-FLOW: wrong variable passed to correct function
    e.g., pipeline passes hello_hash to compute_application_traffic_secrets (needs handshake_hash)
    Comment justifies: "cached for efficiency" — invisible when hello_hash == handshake_hash
  - ORDERING/PLACEMENT: correct functions called in wrong sequence
    e.g., key derived from traffic_secret instead of confirmed_secret (after confirmation step)
    Comment justifies: "negotiation independence" — invisible when confirmation_required=False
  - EPOCH/CONDITION-AWARE: standard path used for all cases, special path never called
    e.g., build_nonce_standard always called even for epoch > 0 (needs build_nonce_extended)
    Comment justifies: "RFC 8446 §5.3 suffices" — invisible when initial_epoch=0

### MASKING RULES (visible data must make buggy == fixed EXACTLY):
  - hello_hash == handshake_hash → stale cache produces correct result
  - confirmation_required = False → confirmed_secret == traffic_secret
  - initial_epoch = 0 → build_nonce_standard == build_nonce_extended
  - Single session → no stale cache across sessions
  - n=1 batch → sum/n == sum (normalize-by-count bug invisible)

### DECOY RULES (correct code that looks wrong):
  - Must have impact ≥30% if removed (so agents who touch it get wrong output)
  - Protect explicitly in instruction.md: "preserve X which correctly does Y"
  - Examples: double-SHA fingerprint, session-bound domain separation, 4+8 byte nonce padding
  - Agents WILL modify protected decoys — that's the compound trap

### SELF-PLAY RESULT → CI PREDICTION:
  ⚠️ CORRECTED Aug 1 — this table only holds when the self-play model is comparable to
  the model CI actually benchmarks with. If you self-play with a STRONGER model than the
  graded one, self-play is an upper bound on solvability, not a prediction.
  Evidence (dynamo-qffewau): 2 strong-model solvers scored 2/2 by code reading alone and
  we nearly redesigned the task again — the real gate then returned pass@2 1/2 and
  pass@5 2/5 (accepted). A 2/2 self-play with a stronger model does NOT mean too easy.
  Always record WHICH model self-played next to the number, and check task.toml's
  model_tested before drawing a conclusion.

  - 0/7 self-play → likely 0/5 CI (strong)
  - 1-2/7 self-play → likely 0-2/5 CI (acceptable)
  - 7/7 self-play → CI will likely pass too (too easy — redesign)
  - Exception: over-engineering trap (agents find bugs but also break decoys) can get
    7/7 self-play identified but still 0/5 CI because fixing + breaking decoy = fail

## PART 10 — OLD vs NEW TEST.SH PATTERN

Older accepted tasks (dynamo-37d03aa, dynamo-c75e93b) use this pattern:
  test.sh copies hidden eval configs from /tests/ to /app/, re-runs pipeline, then pytest
  eval configs live in tests/ (hidden from agent)

  eval configs live in environment/data/ (agent-visible, COPYed into image)

Both patterns work on CI. The newer pattern is simpler and avoids AVA complaints
about "verifier re-runs agent code". Prefer the new pattern for all future tasks.

## PART 13 — OLD-PATTERN TASKS (verifier re-runs the agent's pipeline)

If test.sh runs `python3 pipeline.py` on hidden configs, you have signed up for the
whole E3/E4/E5 family. PART 10 says prefer the new QC_GATE pattern — this part is for
tasks already built on the old one. Everything below was required to get one such task
past AVA + qc_gate.

The problem: at grade time the verifier executes AGENT-AUTHORED code while the answer
key sits on disk. Three concrete exploits, all of which scored reward 1.0 before fixing:

  1. pipeline.py globs /tests/expected_output_*.json and echoes it
  2. /app/output.json is a dangling symlink to /tests/expected_output_1.json
     (dangles during the agent run, resolves at verify time)
  3. pipeline.py writes /logs/verifier/reward.txt itself

Plus two the harness itself introduced:

  4. agent pre-creates the staging dir with actual_N.json -> symlink -> expected_N.json,
     so the verifier compares the answer key against itself   (scored 1.0)
  5. agent plants sitecustomize.py in site-packages, which patches pytest into
     reporting passes                                          (scored 1.0)

The defences that made all five fail:

  - read the expected outputs into memory and DELETE them from /tests before any
    agent code runs; write them back only after the last run, into a 0700 dir
  - chmod 0700 /tests and /logs during the runs; drop the run to uid 65534
  - capture the graded output only after an lstat guard: not a symlink, a regular
    file, and os.path.realpath(p) == p
  - wipe+recreate the staging dir, and write every staged file with
    os.open(p, O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW, 0o600)
  - run BOTH the harness and pytest under `python3 -S` (skips site.py, so a planted
    sitecustomize never executes); restore site-packages via sysconfig.get_paths()
  - test.sh must still literally name test_outputs.py or static checks fail
    ("test.sh does not invoke test_outputs.py") — pass the pytest args FROM test.sh:
      python3 -S /tests/run_pytest.py --ctrf /logs/verifier/ctrf.json \
        /tests/test_outputs.py /tests/test_outputs_2.py -rA
  - assert the isolation actually held (see PART 5 / verifier_coverage)

Residual risk you cannot close in a shared image: the agent is root, so it can edit
_pytest's own source. `-S` stops sitecustomize, not that. Only a separate verifier
image closes it.

  assignment, and state a canonical search order for the tie-break. Any correct
  implementation then agrees regardless of how its search is organised.
  => If your answer can change with resolution order, you have an ambiguity bug.

  A PRE-RELEASE SORTS BELOW ITS OWN RELEASE. `2.0.0b3 >= 2.0` is FALSE. Two hidden
  scenarios were unsatisfiable because of this. Always run the oracle on every
  scenario immediately after generating it — do not batch-generate then test.

  PICK A DOMAIN WITH NO FLOATS. Every graded value here is a string, int, or bool,
  so exact type+value equality is correct and the "tolerance too tight / too loose"
  criteria cannot be argued at all. strict_diff comparing `type(a) is not type(b)`
  also blocks Python's True == 1 from passing a bool where a count is required.

## PART 15 — HOW TO MAKE AGENTS FAIL (distilled from strategy_for_sessions.txt)

PART 7 lists bug SHAPES. This is the DESIGN RECIPE — properties shared by tasks that
reached 0/7 self-play and 0/5 CI, across 19 recorded outcomes. Run it BEFORE writing
bugs; the 18 CHECKs only prove the verifier is sound and say nothing about difficulty.

There are THREE proven difficulty sources. Pick one as primary — you do not need all
three, and several accepted tasks used only one.

### Source 1 — RESTRAINT: agents find every bug and still fail (MOST RELIABLE)
This is the strongest pattern in the log and the one most often overlooked. It does not
require hiding anything.
  - adaptive quadrature (0/5): **ALL agents found ALL 3 bugs (7/7 identification)**, then
    could not stop adding code — GK cross-checks, validators, rewrites. 4/5 fixed correctly
    then broke output with additions; 1/5 crashed rewriting a file not even in bug scope.
  - harmonic decomposition (0/5): all 5 found both bugs, applied correct fixes, then
    over-engineered by rewriting correct modules. *"The ACTUAL difficulty is RESTRAINT
    (knowing when to stop), not bug-finding."*
  - firewall policy (0/5): agents who found all 3 bugs still failed by rewriting pipeline.py
    instead of patching, introducing new bugs.
Why it is the best lever: **"Stating conventions in instruction.md does NOT reduce
difficulty (agents know WHAT but still over-engineer)."** That sidesteps the qc_gate B1
tension entirely — you can be fully unambiguous and still be hard. "Do not rewrite from
scratch" is violated every time under time pressure; it acts as a decoy for the whole
codebase.
CALIBRATION WARNING: for this pattern **self-play is EASIER than CI** (1/7 self-play → 0/5
CI). Do not dismiss a design because self-play solved it.

### Source 2 — CAN'T FIX CORRECTLY: the bug is found but the fix direction is unknowable
  - work-stealing scheduler (0/5): 4/5 agents identified all three bugs and still scored 0.
    Knowing "use CPL priority" does not tell you which DIRECTION to sort into a deque whose
    ends have different operations (owner=bottom, thief=top).
Aim at semantics-under-composition, not at a value.

### Source 3 — CAN'T FIND: the classic hidden-bug task
  - Prometheus histograms (0/7 on the crux bug), Nix store paths, spectral analysis.
Hardest to get right, and the one that repeatedly stalls at 7/7 when the domain is
well-known. Prefer sources 1 or 2 unless you have a genuine domain blind spot.

### Structure — 2+2 is proven; 3 bugs is optional
  - **"The 2-bug + 2-decoy in pipeline.py pattern works RELIABLY across different domains"**
    (spectral, harmonic — both 0/5). Two bugs is ENOUGH when paired with two real decoys.
  - 3 bugs also works (firewall, metrics, quadrature). If you use 3, make them unequal:
    findable ones give false confidence, one is the crux.
  - MULTI-FILE is a lever, NOT a rule. Several 0/5 tasks put every bug in pipeline.py
    (firewall, metrics, harmonic, spectral). It became decisive only for build-dependency
    resolution, a domain so well-known that pipeline-only scored 4/5 — spreading to 3 files
    took it to 0/5. Reach for it when the domain is familiar to models.

### Decoys — measure them, protect them, expect them to be ignored
  - Strength is measured, not assumed: temporal decay weighting = **45% change if removed**;
    2π angular-frequency conversion = **628%**. Verify by "fixing" each decoy on top of all
    real fixes — if reward stays 1, it is not a decoy.
  - **Name them in instruction.md as things to preserve.** Agents modify them anyway —
    that is the trap, and it keeps the task fair. "preserve the temporal relevance weighting
    and angular frequency conversion" → agents still over-fixed.
  - BEST FORM is ACCIDENTAL: realistic code with unusual-but-correct conventions (harmonic
    mean, θ=1.0, n+1 faces for n cells, diagnostic computations that look wrong). Organic
    beats designed — nothing reads as "intentionally suspicious".
  - ADVANCED: a decoy matching the FIX pattern of another bug — an agent who already applied
    that fix elsewhere will not know to preserve it here.
  - CAVEAT: a decoy that traps self-play may not trap CI (reversed base32 trapped 5/7 in
    self-play; CI agents respected the instruction). Do not rely on decoys alone.
  - Decoys need not live in pipeline.py — separate-module decoys work.

### Bug shape
  - Domain-convention violations, not formula errors or anti-patterns. Processing ORDER
    bugs are hardest for agents.
  - **Never leave the correct value sitting in an unused standalone variable** — that is a
    dead giveaway. Hide it inside a returned dict/struct instead (`n_effective` lives only
    in `freq_result`, never as a bare local). "Computed-but-unused" works as a MECHANISM
    (compute `waived_results`, pass `all_results` downstream) but never as a bare unused local.
  - Long function with the bug in the middle — agents read the first and last lines and skip
    inner loops.
  - Domain hierarchy (measured): layered config resolution (K8s/Terraform) 7/7 EVERY TIME;
    build-dependency resolution (Bazel/Gradle) 4/5; CUSUM/changepoint 5-6/7 — all too
    well-known. Working: feature flags, firewall ordering, work-stealing deques, Nix store
    paths, Prometheus histograms, spectral/harmonic signal processing, adaptive quadrature.
  - **Disclosure kills difficulty for textbook conventions.** If the rubric forces you to
    disclose a rule and that makes it trivial, the domain is wrong — switch domains rather
    than hiding the rule (that path failed: removing a variable gave 0/8 but failed
    "unambiguous"; adding the disclosure back gave 6/7).

### Comment justification — keep it
The #1 weapon: 0/7 agents questioned "comprehensive percentile estimation"; "stable
linearization at ambient" was accepted on first read. A comment only reads as a fingerprint
when the code beneath it is ALREADY anomalous — in that case remove the anomaly, not the
comment. Keep comment density uniform across correct and buggy lines.

### Masking
Visible config must COMPLETELY DISABLE each buggy path — literally never executed, and the
agreement an EXACT identity, never a small numeric gap. Worked: cubic polynomial → Simpson
exact → subdivision loop never runs; 1 worker → stealing never runs; 1 histogram source →
merge branch never taken; identity DNAT → pre-NAT == post-NAT; rectangular window →
n_effective == n exactly.

### CORRECTIONS TO EARLIER DRAFTS OF THIS PART (Aug 3)
  - "three bugs, not two" was WRONG. 2 bugs + 2 decoys works reliably (spectral, harmonic).
  - "multi-file is mandatory" was OVERSTATED. It is a lever for well-known domains only;
    firewall / metrics / harmonic / spectral all scored 0/5 with every bug in pipeline.py.
  - "computed-but-unused" needs the nuance above: fine as a mechanism, fatal as a bare
    unused local.
  - RESTRAINT / over-engineering was missing entirely and is the most reliable source.
