These run only on CI and have no local equivalent:

| CI Check | Why not simulatable locally |
|----------|----------------------------|

For these: trust pass2 history (if agents failed before, they'll fail again) and
retrigger if ava_review blocks despite correct code (non-deterministic LLM).

#!/usr/bin/env python3
"""
Local AVA Simulator — tests whether your verifier can be fooled by hardcoding.
Run BEFORE pushing: python3 ava_simulator.py
Attack 1 (copy_expected) always passes locally — that is OK, ignore it.
Attacks 2-5 must ALL be BLOCKED for AVA to pass on CI.
"""

import json, os, shutil, subprocess, sys, tempfile

# ── CUSTOMIZE THESE 4 THINGS FOR YOUR TASK ──────────────────────────────────

REPO_DIR = os.path.dirname(os.path.abspath(__file__))
TASK_DIR = os.path.join(REPO_DIR, "task")
DATA_DIR = os.path.join(TASK_DIR, "environment", "data")
TESTS_DIR = os.path.join(TASK_DIR, "tests")

# 1. Your eval input filenames (in environment/data/)
EVAL1_INPUT = "eval_dataset_1.json"
EVAL2_INPUT = "eval_dataset_2.json"

# 2. Your expected output filenames (in tests/)
EVAL1_EXPECTED = "expected_eval_1.json"
EVAL2_EXPECTED = "expected_eval_2.json"

# 3. Your bug discriminator field + thresholds
# This is the computed field that DIFFERS between buggy and fixed pipeline.
# The buggy pipeline value must be BELOW the threshold.
# eval1 and eval2 thresholds must DIFFER from each other.
# Example for GLMM: sigma2_b 0.048 (buggy) vs 0.799 (fixed), threshold=0.5
DISCRIMINATOR_KEY = ["variance_components", "sigma2_b"]  # nested key path
EVAL1_THRESHOLD = 0.5     # buggy pipeline gives < this, fixed gives > this
EVAL2_THRESHOLD = 2.0     # must be different from EVAL1_THRESHOLD

# 4. Your main computed output field (the field that changes per group when bugs fixed)
# For GLMM: random_effects[group]["blup"]
# For streaming: windows[0]["rates"]["mean_value"]
# For register allocator: interference_edges
def get_computed_field(output, group_or_index):
    """Return the main computed value for a group/index — adapt for your task."""
    return output["random_effects"][group_or_index]["blup"]

def get_all_computed_values(output):
    """Return list of all computed values — adapt for your task."""
    return [v["blup"] for v in output["random_effects"].values()]

def get_group_keys(output):
    """Return the set of group/index keys — adapt for your task."""
    return set(output["random_effects"].keys())

def get_config_groups(config):
    """Return expected group keys from input config — adapt for your task."""
    return set(config["groups"])

def get_config_n_obs(config):
    """Return n_obs from input config — adapt for your task."""
    return config["n"]

# ── END CUSTOMIZATION ────────────────────────────────────────────────────────


def get_nested(obj, keys):
    """Get nested dict value by key path list."""
    for k in keys:
        obj = obj[k]
    return obj


def approx_equal(a, b, rel_tol=1e-3):
    if isinstance(a, (int, float)) and isinstance(b, (int, float)):
        if b == 0.0: return a == 0.0
        if abs(b) < 1e-10: return abs(a) < 1e-6
        return abs(a - b) / abs(b) < rel_tol
    return a == b


def check_tests(output_dir, label):
    """Run key assertions. Returns True if attack SUCCEEDED (bad), False if BLOCKED (good)."""
    print(f"\n{'='*60}\nATTACK: {label}\n{'='*60}")

    out1 = os.path.join(output_dir, "output_eval_1.json")
    out2 = os.path.join(output_dir, "output_eval_2.json")
    cfg1 = os.path.join(DATA_DIR, EVAL1_INPUT)
    cfg2 = os.path.join(DATA_DIR, EVAL2_INPUT)
    exp1 = os.path.join(TESTS_DIR, EVAL1_EXPECTED)
    exp2 = os.path.join(TESTS_DIR, EVAL2_EXPECTED)

    failures = []

    def check(name, fn):
        try:
            fn()

## ADDITIONAL LEARNINGS — dynamo-04a62da (July 27, 2026)

### 1. Module docstrings can leak the fix (AVA verifier_coverage blocker)

If a module file (not pipeline.py) has a docstring that says what the CORRECT value
should be, AVA flags it as answer leakage — the agent reads it and instantly knows the fix.

**Example that blocked us:**
```python
# blup_calculator.py
"""B_list — should be the CENTERED basis, one per subject."""
# ↑ This directly tells the agent the fix for Bug 2
```

**Fix:** Scan and neutralize before every push:
```bash
grep -rn "should be\|must use\|correct.*is\|use.*instead" task/environment/data/*.py | grep -v pipeline.py
# Any result = potential leak — rewrite as neutral description
```

**Rule:** Docstrings describe WHAT a parameter is, never WHAT IT SHOULD BE.

---

### 2. Different thresholds per eval dataset (AVA C3 hardcoding fix)

The input-derivation test needs a computed threshold that:
- Fails on the buggy pipeline output
- DIFFERS between eval1 and eval2 (prevents cross-hardcoding)

**Threshold design:**
```python
# Step 1: run buggy pipeline on eval1 → get r2_cond_buggy_1
# Step 2: run fixed pipeline on eval1 → get r2_cond_fixed_1
# Step 3: set threshold T1 between them
# Step 4: repeat for eval2, set threshold T2 ≠ T1

# Example (dynamo-04a62da):
# eval1: r2_cond buggy=-0.08, fixed=0.997 → T1=0.5
# eval2: r2_cond buggy=0.117, fixed=0.9999 → T2=0.8
# T1 ≠ T2 ✓ → hardcoding eval1 fails eval2's stricter test

def test_eval1_output_derived_from_input():
    assert output["diagnostics"]["r2_conditional"] > 0.5  # T1

def test_eval2_output_derived_from_input():
    assert output["diagnostics"]["r2_conditional"] > 0.8  # T2 ≠ T1
```
